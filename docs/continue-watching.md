# Emby 首页继续观看

Nook 的 Emby 兼容首页将断点续播和下一集推荐合并为一个「继续观看」列表。

| 观看状态 | 首页显示 |
| --- | --- |
| 电影未看完 | 原电影，保留用户的播放位置 |
| 剧集当前集未看完 | 当前集，保留播放位置 |
| 当前集已看完，后面有未看集 | 下一集；尚未播放时进度为 0 |
| 已看完最后一集 | 不再显示该剧，不恢复更早的旧断点 |

同一部剧只保留一个条目，按这部剧最近一次观看的时间参与整体排序。没有观看历史的剧不会自动进入列表。播放记录按 Nook 用户隔离，继续应用媒体库访问权限、内容分级和已删除媒体过滤。

网页与 Emby 兼容客户端上报播放进度时，达到所属媒体库的「播放完成阈值」即标记为已观看；默认 90%，可在「管理媒体库 → 对应库的更多菜单 → 播放设置」中设置为 1–100%，新建媒体库时也可填写。各库独立，保存后下一次上报进度时生效，不批量改写已有观看记录。时长未知时不会自动标记；只读的远程 Emby 挂载库使用默认 90%。

同一播放设置中还可配置「最小续播百分比」（默认 5%）和「最短可续播视频时长」（默认 180 秒）。最小比例须小于完成阈值，两个最小值分别设为 0 可关闭对应限制。按视频总时长而非已播放秒数判断最短时长；短视频仍可达到完成阈值并标记已观看，但不会自动续播。时长未知且仍有最小限制时，不自动续播。

原始观看进度仍保留用于观看历史和统计，读取网页续播位置、Emby UserData、IsResumable 和当前/下一集候选时统一判断是否允许续播。保存最小续播设置后，下次读取即生效，不改写观看时间或原始进度。远程 Emby 挂载库只读，使用默认 5% 和 180 秒。

观看历史列表不再返回查不到媒体的占位卡片，已删除的本地媒体在分页之前过滤。读取历史或继续观看不会删除播放记录，远程超时也不删除；已有媒体记录恢复可用后可重新显示其历史。此处保留的是原媒体 ID 下的状态，不会把新建媒体 ID 自动关联到旧记录。

客户端详情、媒体列表及最近添加等返回的已观看标记统一读取保存的完成状态，不在展示时按百分比重新计算。命中元数据缓存后也会读取当前用户的最新播放状态，手动标记已观看或未观看同样适用。

## 接口约定

- `GET /emby/Users/:userId/Items/Resume` 与 `/emby/Items/Resume` 返回合并列表，支持 `Limit`、`StartIndex`，以及通过 `ParentId` / `SeriesId` 收窄范围。小写别名保持可用。
- `GET /emby/Items?Filters=IsResumable` 保留原意：只返回真正存在未完成播放位置的条目，不加入尚未播放的下一集。
- 首页不再提供单独的 NextUp 内容：不带剧集作用域的 `GET /emby/Shows/NextUp` 返回合法的空列表。此行为也适用于不读取服务器首页偏好的客户端，避免两个栏目返回相同卡片。
- `GET /emby/Shows/NextUp?SeriesId=…`、`/emby/Shows/:id/NextUp` 等按剧查询继续返回该剧当前应看的集，供详情页「继续播放」使用。当前集未看完时仍返回它本身。
- DisplayPreferences 默认保留 `homesection1: resume`，将原来的独立 `homesection3: nextup` 改为 `none`。

## 远程挂载与边界

挂载的远程 Emby 使用 Nook 本地播放历史计算续播和下一集，不使用上游共享账号的观看状态。远程媒体按挂载权限过滤，并支持按远程媒体库、剧或季收窄。

候选范围为最近 200 条有效播放历史，单页最多 100 项。先按剧去重、按观看时间排序，再分页。本地条目总数准确；远程详情仅按当前页面需要并发补齐，未补齐候选的总数沿用上界估算，以避免为了统计而请求全部远程历史。远程读取共用 8 秒预算，慢源或不可用条目不会阻止其余本地内容返回。

播放设置保存在媒体库表，升级时新增最小续播比例和最短时长字段；不删除或批量改写现有观看进度。升级后客户端可能需要刷新首页以更新缓存的栏目。已验证 HTTP 协议流程及模拟远程服务器，尚未做 SenPlayer 真机升级联调。
